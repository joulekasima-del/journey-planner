# Journey Planner Strategic Roadmap

Version: 1.0

Status: Active

---

# Purpose

This roadmap defines the long-term evolution of the Journey Planner.

It is a strategic document.

It does not track sprint implementation.

Implementation progress belongs in:

- BUILD_TRACKER.md
- Release Notes

This roadmap answers one question:

**What are we building over the lifetime of the product?**

---

# Product Vision

Build the most trusted Journey Planner for conservation-based local travel.

The platform should help visitors design meaningful journeys while strengthening local communities, protecting nature, and making travel calmer, more educational, and more personal.

---

# Roadmap Philosophy

Every phase must create usable value.

Each completed phase should leave the product in a stable, releasable state.

Do not begin a new phase until the previous phase reaches its defined completion criteria.

---

# Phase I — Foundation

Status

Completed

Purpose

Establish the permanent foundation shared across all future products.

Completed Work

- Working Protocol
- Product philosophy
- Creative Framework
- Pixel Language
- Master Palette
- Art Direction
- Asset specifications
- Production workflow
- AI workflow
- Documentation standards
- Bootstrap foundation

Deliverable

A stable studio foundation that future projects can inherit.

---

# Phase II — Scout Workspace

Status

Planned

Purpose

Build the internal operating system used to discover, verify, organise, and maintain local experiences.

Primary Users

Scout

Objectives

- Experience database
- Field data collection
- Categorisation
- Verification workflow
- Media management
- Mapping tools
- Geographic information
- Host records
- Availability management
- Internal dashboard
- Publishing workflow

Definition of Success

A Scout can confidently manage hundreds of verified experiences without relying on spreadsheets or external tools.

---

# Phase III — Explorer Platform

Status

Planned

Purpose

Build the public-facing Journey Planner.

Primary Users

Explorer

Objectives

- Account system
- Journey creation
- Multi-day planning
- Interactive map
- Experience discovery
- Journey timeline
- Saved journeys
- Availability viewing
- Geography integration
- Weather integration
- Responsive interface

Definition of Success

A first-time visitor can independently plan a complete journey with confidence.

---

# Phase IV — Booking System

Status

Planned

Purpose

Connect planning with reservation.

Objectives

- Booking workflow
- Availability engine
- Payment integration
- Reservation management
- Confirmation flow
- Booking history

Guiding Principle

Booking supports the journey.

Planning always comes first.

Definition of Success

Visitors can complete bookings without disrupting their planning experience.

---

# Phase V — Travel Companion

Status

Planned

Purpose

Support visitors before and during travel.

Objectives

- Personal journey dashboard
- Travel reminders
- Journal integration
- Digital itinerary
- Offline reference materials
- Companion guidance
- Reflection tools

Guiding Principle

Technology should quietly support the traveller throughout the journey.

---

# Phase VI — Host Portal

Status

Planned

Purpose

Allow local partners to manage their own information.

Primary Users

Hosts

Objectives

- Availability updates
- Booking management
- Experience editing
- Schedule management
- Media updates
- Profile management

Definition of Success

Hosts can maintain their information without requiring platform administrators.

---

# Phase VII — Community Platform

Status

Future

Purpose

Strengthen relationships between visitors and local communities.

Possible Features

- Community stories
- Local articles
- Seasonal updates
- Educational resources
- Conservation projects
- Community announcements

---

# Phase VIII — Ecosystem Expansion

Status

Future

Purpose

Expand the platform while preserving quality.

Possible Directions

- New community partnerships
- Educational programmes
- Research partnerships

# Release Philosophy

Every completed phase should produce:

- Stable documentation
- Stable implementation
- Verified functionality
- Clean Git history
- Updated roadmap
- Updated release notes

---

# Backlog Rule

Ideas discovered during development belong in:

09_BACKLOG.md

Roadmap phases should not expand without explicit approval.

---

# Measuring Success

Success is measured by:

- product quality
- traveller confidence
- host trust
- local community benefit
- maintainability
- long-term sustainability

Not by feature count.

---

# Long-Term Vision

Create a platform where planning meaningful journeys becomes as natural as opening a map.

Visitors should feel informed rather than overwhelmed.

Communities should feel supported rather than exploited.

Technology should quietly connect people with places while preserving the character that makes those places worth visiting.

---

# Guiding Principle

Build slowly.

Build thoughtfully.

Build something that communities will still value many years from now.

---

# Amendment Rule

Changes to this roadmap require explicit locked approval.

Implementation milestones may evolve.

The long-term vision should remain stable unless the product itself changes direction.
