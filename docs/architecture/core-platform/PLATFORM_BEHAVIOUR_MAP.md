# Core Behaviour Rules

| Rule | Behaviour |
|---|---|
| Journey before Booking | Planning comes first; reservation comes later |
| Discovery before Commitment | Explorers should freely explore before deciding |
| Booking attachment | Booking is always attached to an Itinerary Item |
| Journey independence | A Journey may exist without any Bookings |
| Verified information | Only verified Experiences should appear publicly |
| Availability boundary | Availability indicates possible reservation opportunities, not guaranteed Booking |
| Scout quality role | Scouts verify and maintain Experience quality and accuracy |
| Calm technology | Interfaces should reduce stress and avoid urgency |

---

# Role Behaviour

| Role | Approved Behaviour |
|---|---|
| Explorer | Creates Journeys, discovers Experiences, plans travel, makes Bookings, learns through the platform |
| Scout | Visits locations, verifies information, collects photographs, records local knowledge, maintains Experience quality |
| Host | Future role; manages availability and reservations when approved |
| Administrator | Future role; provides operational oversight when approved |

---

# Product Behaviour Filter

Future behaviour should be evaluated against the approved philosophy:

1. Does it strengthen meaningful journeys?
2. Does it support local communities?
3. Does it encourage conservation?
4. Does it improve hospitality?
5. Does it reduce complexity?
6. Does it remain calm and trustworthy?
7. Will visitors remember the experience more than the technology?
